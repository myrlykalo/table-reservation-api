# Серверная часть сервиса резервирования столиков

Учебный API одного ресторана. Гость проверяет наличие мест, оформляет бронь и может её перенести или отменить. Сотрудник видит журнал за местную дату и добавляет столы. Документация OpenAPI доступна в запущенном приложении.

## Запуск в Windows PowerShell

Нужен Python 3.11 или новее с модулем SQLite. Проверено на Python 3.13.3. Выполните команды из корневой папки репозитория.

```powershell
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
$env:BOOKING_ADMIN_KEY = [guid]::NewGuid().ToString()
.\.venv\Scripts\python.exe -m uvicorn reservation.api:app --host 127.0.0.1 --port 8000
```

Откройте [интерактивную документацию](http://127.0.0.1:8000/docs) или [схему OpenAPI](http://127.0.0.1:8000/openapi.json). Swagger UI загружает оформление из интернета. Локальная схема и пример ниже работают без интернета после установки зависимостей. Для запуска без инструментов тестирования достаточно `requirements.txt`.

Linux и macOS используют те же команды сервера и тестов с интерпретатором `.venv/bin/python`. Создать окружение можно командой `python3 -m venv .venv`, задать служебный ключ — `export BOOKING_ADMIN_KEY="$(.venv/bin/python -c 'import secrets; print(secrets.token_hex(32))')"`.

## Демонстрация и тесты

Во втором окне PowerShell перейдите в ту же папку. Для демонстрации используется свободный стол на восемь гостей на завтра, 19:00 МСК.

```powershell
.\.venv\Scripts\python.exe demo.py
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Пример создаёт учебную бронь, повторяет исходную заявку с тем же ключом, переносит время на 19:15, отменяет и проверяет доступность. Если во втором терминале установлен тот же `BOOKING_ADMIN_KEY`, он также читает журнал. Автотесты используют отдельные временные базы и фиксированные часы. Набор проверяет в том числе восемь одновременных заявок на один столик и четыре повтора одной заявки.

## Правила зала

- Время работы ежедневно с 12:00 до 23:00, часовой пояс UTC+03:00. Принимаются метки времени вида `2026-11-25T19:00:00+03:00` или `2026-11-25T16:00:00Z`. Для ручной демонстрации выберите будущую дату.
- Размер группы 1–8 человек. Продолжительность визита 30–180 минут с шагом 15 минут. Начало также кратно 15 минутам. Доступны сегодня и следующие 30 календарных дней. Завершить визит можно ровно в 23:00.
- Назначается наименьший свободный стол достаточной вместимости. При равенстве выигрывает меньший идентификатор. В начальном зале шесть столов на 2, 2, 4, 4, 6 и 8 мест. Каждая группа занимает один стол.
- В момент окончания интервала стол уже свободен. Перенести или отменить подтверждённую бронь можно до начала визита. При неудачном переносе сохраняются прежние условия. Отменённая бронь остаётся в журнале.
- Клиент заранее создаёт случайный UUIDv4, отдельный на каждую бронь, например `[guid]::NewGuid().ToString()`. Он передаётся как `Authorization: Bearer <ключ>`. Сервер хранит SHA-256 ключа. Публичный идентификатор брони и секретный ключ — разные значения. Используйте HTTPS при размещении за пределами локального компьютера.
- Повтор исходного POST с прежним ключом возвращает текущее состояние той же брони и код 200. Другая заявка с тем же ключом даёт 409. Храните ключ до завершения визита.

## Маршруты

| Метод | Путь | Доступ и назначение |
|---|---|---|
| GET | `/health` | Процесс отвечает |
| GET | `/api/availability` | Свободные столики по `start_at`, `duration_minutes`, `party_size` |
| POST | `/api/reservations` | Гостевой ключ, время и состав заявки, `guest_name`, необязательный `phone` |
| GET | `/api/reservations/{id}` | Владелец открывает бронь |
| PUT | `/api/reservations/{id}/visit` | Владелец задаёт новое время, длительность и число гостей |
| DELETE | `/api/reservations/{id}` | Владелец отменяет бронь |
| GET | `/api/admin/reservations?day=YYYY-MM-DD` | Сотрудник читает журнал по дате начала визита |
| POST | `/api/admin/tables` | Сотрудник добавляет столик по обозначению и вместимости |

Сотрудник передаёт заголовок `X-Admin-Key`. При отсутствии настройки служебные маршруты отвечают 503. Поиск не раскрывает имена и телефоны. Клиентские ошибки имеют поле `detail`. Код 409 указывает на конфликт заявки, 422 — на ошибку входных данных, 503 с заголовком `Retry-After` — на занятость хранилища.

## Устройство и хранение

`domain.py` содержит модель визита и правила расписания. `service.py` описывает сценарии, зависящие от портов в `ports.py`. `sqlite_store.py` реализует эти порты. `api.py` принимает запросы и связывает компоненты. Схема находится в `reservation/schema.sql`.

SQLite хранит данные в `.data/restaurant.sqlite3`. Путь задаёт переменная `BOOKING_DB`. При запуске сервер создаёт недостающие таблицы и добавляет исходный зал. Свободное место проверяется заново под `BEGIN IMMEDIATE`. Первичный ключ `(table_id, slot_start)` не позволяет записать одну четверть часа для двух компаний. Для переноса все изменения входят в одну транзакцию. При работе с настоящей базой храните её на локальном диске сервера вне синхронизируемой папки. Для демонстрации можно указать путь в `$env:TEMP` до запуска Uvicorn.
